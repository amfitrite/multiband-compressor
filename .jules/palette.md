## 2026-02-20 - JUCE Tooltips & Layout Mathematics
**Learning:** In JUCE, adding string descriptions via `setTooltip()` is not enough. You must instantiate a persistent `juce::TooltipWindow` instance (e.g., as a class member in the editor) to actively intercept hover events and render the tooltip. Furthermore, when using JUCE's procedural `juce::Rectangle::removeFromTop()` layout mechanics, if the overall window height is mathematically smaller than the sum of the components, the bottom components will silently clip or squash rather than scrolling or throwing an error, leading to poor non-tactile knob proportions.
**Action:** Always verify that a `TooltipWindow` exists before relying on tooltips for accessibility in JUCE, and ensure the root `setSize()` safely encompasses the cumulative pixel demands of child elements to maintain true 1:1 hardware aesthetics.

## 2026-02-23 - Visual Affordances for Specialized Controls
**Learning:** Using identical UI elements (like generic rotary sliders) for conceptually different parameters (e.g. Gain vs Warmth) can lead to a slightly confusing micro-UX, as users must read small text labels to differentiate them. Adding visual affordances natively mapped to the parameter's semantic meaning (e.g., a glowing tube-like core for a Warmth knob) acts as an intuitive cognitive shortcut for the user.
**Action:** Use component properties (e.g., `slider.getProperties().set("isWarmthKnob", true)`) paired with dynamic LookAndFeel drawing overrides to build semantic visual mapping for specialized controls, improving software interface tangibility without cluttering the layout.
